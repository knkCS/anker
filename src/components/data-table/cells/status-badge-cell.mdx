# StatusBadgeCell

Renders a `StatusBadge` for a string status value. Map each status string to a **tone** with `toneMap` — the preferred mapping, which follows the theme in light and dark mode (tones: `success`, `warning`, `danger`, `info`, `neutral`, `accent`; see the `StatusBadge` docs). Statuses not in the map fall back to `fallbackTone`.

```tsx
<StatusBadgeCell
  value={row.status}
  toneMap={{ done: "success", failed: "danger", running: "info" }}
  fallbackTone="neutral"
/>
```

## Data-driven colours

`colorMap` maps a status to a colour that arrives as **data** — user-picked status colours stored in the backend — and `fallbackColor` (default `"gray"`) covers the rest. Never write colour literals into it: a status known in code takes a tone.

<Canvas of={Stories.DataDrivenColorMap} />

## Tone and colour together

When both are given, a mapping beats a fallback, and at each level a tone beats a colour:

1. `toneMap[value]`
2. `colorMap[value]`
3. `fallbackTone`
4. `fallbackColor`

So a value in both maps takes its tone:

## With Tooltip

The optional `tooltip` prop wraps the badge in `<Tooltip>` from `@knkcs/anker/primitives`. Use it for status descriptions, full metadata payloads, or any "expand on hover" affordance that doesn't fit on the badge label.

<Canvas of={Stories.WithTooltip} />

## With Icon

The optional `icon` prop renders a `ReactNode` inline before the label inside the badge — typically a small `lucide-react` glyph. Pairs naturally with status values like 2FA "On" / "Off".
